# 说画 · Jev + tldraw

**中文** | [English](README.en.md)

用连续语音或文字操作 tldraw 画布。自然语言理解完全由 Jev 完成：没有本地意图解析、同音替换词表或无密钥回退。文字输入与语音最终转写共用同一队列。

## 启动

需要 Node.js 20.19+ 或 22.12+、npm；语音需要麦克风权限——浏览器识别另需支持 SpeechRecognition，本地识别见下文，不依赖它。

```bash
npm install
cp .env.example .env
# 填入 TYPESAFE_API_KEY
npm run dev
```

支持 `.env` 和 `.env.local`，已有环境变量优先。API 监听 `127.0.0.1:8787`；打开终端显示的 Vite 地址。密钥只由服务端读取。界面显示“Jev 未配置／可用／请求失败”；配置存在表示可发起请求，不是启动时另发探测请求。请求失败显示具体原因，不改画布。

## 本地语音识别（可选）

默认用浏览器的 SpeechRecognition。也可以切到本机 Whisper：准确率更高，而且能用示例句做 decoder 偏置——“结束”这类只差声调的同音错词只有本地模型压得住。代价是要自己起一个服务。

服务不在本仓库里，装在 `~/.cache/whisper.cpp`：

```bash
cd ~/.cache/whisper.cpp && ./serve.sh medium 8788   # 参数是「模型 端口」
```

脚本已固化三个开关：`--vad`（防静音段凭空编字）、`--prompt`（领域偏置，取自同目录 `prompt.txt`）、`-l zh`。**改了 `prompt.txt` 要重启服务**，边上的 `--prompt` 只在启动时读一次。

界面开机探测 `GET /api/asr/status`：本地服务可用就默认走本地，否则回退浏览器识别。

`server/app.ts` 的 `/api/asr` 只做转发，**不解析音频**：浏览器的 `FormData`（multipart）原样送给 whisper-server 的 `/inference`。这里踩过一个坑——早先按 `Content-Type: audio/wav` 收二进制再重包成 multipart，与前端实际发的 multipart 对不上；`express.raw` 遇到不匹配的 Content-Type 是**跳过解析**而不是报错，`request.body` 于是成了空对象，每次识别都稳定 400，而错误文案写成“识别服务返回 400”，把排查方向指向一直好着的 whisper。所以验证必须用前端同款格式：

```bash
curl -s -X POST -F "file=@sample.wav" -F "response_format=json" http://127.0.0.1:8787/api/asr
```

发裸 WAV（`--data-binary` 配 `Content-Type: audio/wav`）转发层也支持——那是给 curl 调试用的，本地会补上 multipart 壳——但**只用它验证会假通过**。`server/asr-proxy.test.ts` 用假上游把这条链路锁住：multipart 原样透传且音频字节完好、裸 WAV 补壳、上游失败的原因透传、空 body 就地拒绝。

## 演示目标：一个圆，决定不再当普通的圆

目标是一段约 60–90 秒的连续画布变化：创建圆 → 改橙 → 放大一档 → **按当前尺寸放大到 2 倍** → 在下方创建**宽高都等于圆当前实际外接尺寸**的方形 → 把方形移到圆右边 → 写字 → 连线 → 撤销这条连线 → 重连 → 复制原来的橙色圆 → 只把新副本改蓝并缩小。倍数与参照尺寸都必须从执行时的真实画布状态计算，不能从话语里猜像素值。这里是**待打通的完整演示目标**，不是当前已支持功能清单。

## 三段演示

三段脚本都从干净画布开始，按顺序照念即可。括号里是这句话在做什么，也是可以让观众盯着看的那一点。台词在真实密钥下逐句复跑过（`work/demo-script-probe.mjs`）。

### 一、流程图：相对位置、文字容器、按类型连线

1. 在这里建一个圆
2. 在它下面建一个矩形（“它”不是“画布上的矩形”，而是上一步刚建、此刻被选中的那个）
3. 在它下面建一个菱形
4. 在圆里写“开始”（文字写进已有图形，不新建文字对象；不带引号的“在圆中间写一个开始”同样写进圆——容器由代码按形状名或序号定，量词“一个”不是数量）
5. 在矩形里写“处理订单”
6. 在菱形里写“结束”
7. 把圆连到矩形（两端都明说了类型，不需要框选，也不需要鼠标悬停）
8. 把矩形连到菱形
9. 把圆放大一点（圆变成 154×154，矩形仍是 140 宽，两边宽度不一致）
10. 把连到“结束”的矩形改成和圆一样宽
11. 看全部

第 9–10 句是这一段最值得看的地方。要让观众看清第 10 句在做什么，就得先有第 9 句把两边宽度拉开：第 10 句的目标不是模型挑出来的 ID，而是代码按真实箭头绑定筛出的唯一一个（连到“结束”的矩形只有一个），宽度也不是模型估的，而是执行前从圆的真实边界读出来的。

### 二、一排卡片：复制、排列、序号、对齐

1. 在这里建一个矩形
2. 再复制三个（“再”是新增三个，最终四个）
3. 把它们排成一行
4. 第一个改成红色
5. 第二个改成橙色
6. 第三个改成绿色
7. 第四个改成蓝色
8. 让它们顶对齐
9. 看全部

序号按创建顺序读，与画布坐标无关，所以复制出来的副本可以按顺序逐个上色；对准行和顶对齐都作用在整组上。

### 三、结构图：用箭头关系反指对象

1. 在这里建一个圆
2. 在它里面写“开始”
3. 在它右边建一个矩形
4. 在它里面写“审核”
5. 在它右边建一个菱形
6. 在它里面写“结束”
7. 把圆连到矩形
8. 把矩形连到菱形
9. 把连到“结束”的那个矩形改成橙色
10. 把连到“审核”的那个圆形锁定
11. 看全部

第 9、10 句里没有位置、没有序号、也没有“它”。这两句要等箭头存在之后才成立：说“连到‘结束’的那个矩形”时，画布上确实只有一个矩形连到“结束”。说反方向（“从 X 连出去的那个”）目前判定不稳，会如实澄清而不是猜。

### 两个混合指令

一句话里放多个步骤时按逗号／“然后”切分，每个分句各判一次，最后合成一条命令整体执行、整体撤销：

- **有先后依赖**：「在这里建一个圆，然后在它里面写“开始”，然后把它改成绿色」——建圆、写字、改色三步，后两步落在前一步刚建的对象上。
- **各自独立**：「第一个改成蓝色，第二个改成红色」——两个互不依赖的目标，一次改完。

最多三个分句、整条指令最多 4 次请求。切分只认逗号、分号与“然后”，所以脚本里的分句要用标点隔开。

## 行为与能力

- 创建圆、矩形、菱形、独立文字；添加/替换/删除标签；删除对象（说“清空画布”“清空所有内容”删掉画布上的全部对象，和“全部删除”同义，不会只删当前焦点那一个）。
- 说“在方形中间写一个结束”“在菱形里边写上开始”时，那个已有对象就是文字的接收容器，由代码定，不问模型：句中按形状名或序号**唯一**指名才兜底（“第几个”仍按序号答，由执行层按创建顺序取对象），文字内容里的图形名不算容器（“在方形里写上圆形”写进的是方形）。同一个容器也是删除文字的靶子：“把方形里写的字删掉”删的是方形的文字，不是画布上别的字。有多个同名对象时不猜，照旧澄清。动词不用挑：“写／放／加／填／添／标／记／输入”后面接的是文字还是图形，按要放进去的那个词判断——是图形名就是要新建（“在方形里加一个圆”），否则就是写进去（“在方形中间加一个开始”），而这类动词在模型眼里天生摇摆，判据一律由代码拿。反过来，往对象**内部新建图形**目前做不到，会如实说“还不能把新图形建在另一个对象的内部”，不会拿两个都走不通的选项让用户挑。
- 调整整体尺寸、宽高、预设颜色、填充、描边、文字颜色；默认相对缩放每档 ±10%。明确尺寸只支持像素，不猜数字或单位。
- 移动的三种基准：按方向加像素位移（“往右移一点”，默认 16 像素；说“远一点／多一点”是 80 像素，“一点点／稍微”是 8 像素）、鼠标位置（“移到这里”）、另一个对象（“移到方形右边”，整组贴到那一侧的外边）。复制单个对象（最多新增 19 个）、横纵排列、绑定连线、撤销与重做。连线两端可以说类型（“把圆连到矩形”），也可以说序号（“把第一个和第二个连起来”“把第二个连到第一个”）：起点终点按原句说的顺序取，方向不会被升序抹掉，也不需要框选或鼠标悬停。说“挪到最右边”“贴到底部”这类位置极值不执行也不猜：代码没有可贴的边界，旧实现会把它落到默认 16 像素上，看上去挪了、其实只动一点点，所以现在如实说清做不到，并给出可用说法（具体位移，或框选后“排成一行”“顶对齐”）。
- 改变多个对象之间的秩序：六个方向的对齐（左／右／顶／底／左右居中／上下居中）与前后层叠（最前／最后／上移一层／下移一层）。两者是同一族关系，共用一道判别题；方向由 Jev 挑，位移由代码按真实边界计算。少于两个对象时先澄清。
- 锁定与解锁：锁定后的对象不能被选中或修改。执行层先按真实锁定状态过滤再翻转，所以“锁上”不会把已经锁定的那批变成解锁。目标全都已处于要求的状态时报错而不是静默成功（“这些对象已经锁定／没有锁定”），否则紧接着的一句“撤销刚才那个锁定”会通过校验却撤掉更早的真实操作。
- 改变取景范围：说“看全部”“全览”“看整体”把整个画布纳入视野，说“聚焦到选中的”只对准当前选区。相机操作不碰任何对象、不进撤销栈，因此也不会成为之后一次“撤销”的目标；没有选中对象时说“聚焦到选中的”会如实降级为看全部并说明，不假装执行了聚焦。这些取景口令是闭集说法、解释唯一，整句命中时在本地直接兑现、不经过模型（“看镜头”也在其中）；句子里还有别的动作时仍走 Jev。
- 选择对象：整句说“全选”会在本地直接选中当前页面的全部可选对象（锁定对象按 tldraw 的规则跳过），不请求 Jev，也不修改图形。若当前选区在容器内，仍以整个页面为范围；含其他动作的复合句不会被这条本地口令截获。
- 撤回已完成的操作与否定分开判断：说“撤销”“撤回刚才那一步”会撤销上一步，并在反馈里列出实际被改动的对象（按撤销前后画布差异计算，不猜是哪条命令）。只有动词、没有宾语的“撤销／撤回”有时会被决策层读成“放弃自己正要说的请求”，而同一次请求里操作维度已经以 0.99 的把握判为撤销——两个答案冲突时取更明确的那个，所以这类说法照常执行；反向的“不要撤销”“别撤回”判不出这个操作，仍然保留画布。不指向那一步的放弃表达（“算了”“不要了”“别画了”）不会被自动当作撤销；画布上刚有操作时，澄清提示会指出可以说“撤销”。画布上没有可撤操作时不提示。
- 明确类型优先于选区：说“方形”只匹配矩形；多个同类或没有对应图形时澄清。要一类图形的整体就说“全部方形”“所有圆形”，那是页面上所有这一类对象，和“全部”（选区或会话组）不是一回事。
- 序号引用按**全局创建顺序**取号：说“第二个”就是画布上的第 2 个，不管它是什么形状。形状名只作校验——第 2 个不是方形时如实澄清“第 2 个不是矩形”，不会悄悄滑成“方形里的第几个”而落到另一个对象上。**但序数直接修饰形状名时数的是那一类里的第几个**：「第二个圆形」是画布上第 2 个圆形（在「圆·矩·圆」上就是标着 3 的那个），由代码按候选换算，不经过模型。两种读法都成立却指向不同对象时（画布上第 2 个是圆形，而第 2 个圆形是第 3 个）不替用户挑，把两个候选摆出来让用户一句话定；两类读法都走不通时说清画布上有几个。隔着方位词或动词的图形名不算被序数修饰（“在第二个下面画一个圆”里的圆是新对象，“把第二个改成圆形”里的圆形是目标值）。同一套换算也作用于文字容器（“第二个圆形中间写一个结束”）、连线两端（“把第一个圆形和第二个圆形连起来”）与方位参照（“在第二个圆形下面画一个圆”）：紧跟方位词的那个形状名归参照物，剩下的归目标。支持单个（“第二个”）、并列（“第一和第三个”“第一、第三个”）、范围（“前三个”“后两个”“最后两个”；“前几个”按三档处理，与“大一点”折算 10% 同类）。序号不包含箭头。删除吃同一套说法：说“把第三个删除”只删第 3 个，说“把第二和第三个都删掉”删两个，说“删除全部方形”删掉这一类的全部，说“把第三个的填充删掉”只清填充；删除不可逆，所以序号读不到、或说了形状而那个序号不是该形状时一律澄清，绝不猜一个对象删掉。
- 画布左上角常驻显示每个对象的位置编号，说的数字和屏幕上的数字是同一个（「第 N 个 + 形状名」除外：它数的是那一类里的第 N 个，反馈里会写出换算后的编号，例如「第 3 个圆形」）。编号取的是**位置序号**而不是内部自增号：删掉一个之后内部号会跳（1、3、4），而“第二个”指的始终是当前位置的第二个，两者必须一致，否则屏幕上的数字和嘴里的数字不是一回事。
- 只有省略指代才使用选区或会话焦点。
- 没框选时目标来自上一次语音操作的会话焦点；焦点也没有时按操作提示框选——对齐、排列、锁定、解锁需要多个对象，所以提示是“请先框选……”而不是笼统的“一个目标”。说“全部”指选区或会话组，不等于页面上的全部对象；说“全部方形”才是页面上所有的这一类图形。对齐与排列现在都接受框选多个（排列此前只认“全部……”，拒收框选多个）。
- 序号与范围说法本身就是指一批（“第一和第三个”“前三个”“全部方形”），数量由说法决定，不再要求它们恰好一个。执行层仍然逐个校验：范围里混进别的形状会如实报错，不会静默跳过。
- Jev 可从真实候选中按现有文字、空间或连接关系选择对象；仍会有保守拒绝，不能保证所有自然表达或误听都能恢复。
- 关系定位：说“连到‘结束’的那个矩形”时由代码按真实箭头绑定筛选目标并要求唯一，不采用模型挑出的对象 ID。句中同时出现另一个对象标签（尺寸参照、落点位置）时，锚点只认连接方向那句话里的那个对象。方向说反（“从‘开始’连出去的矩形”）目前判定不稳，会如实澄清而不是猜；零候选或多候选同样澄清，不退回当前选区。
- 参照编辑把**被修改对象、提供值的参照对象、目标属性、来源属性**分开判断，再从当前画布读取实际值。已有对象支持参照宽度、高度、整体颜色、填充、描边和文字颜色；宽度与高度可交叉参照，例如“把第二个高度改成和第一个宽度一样”已在真实 Jev 与页面路径中把第二个高度改为第一个的当前宽度。其他跨属性组合明确拒绝，不能默默当成同属性。矩形先建、圆作为第二个图形并放大到 154×154 后，“把矩形的宽度调成和‘第二个’一样”在真实 Jev 与页面路径中只把矩形宽度改为 154。把圆内部填成橙色后说“把矩形的填充改成和圆一样”，页面也复制了填充模式与颜色。tldraw 基础图形的轮廓与填充共用颜色，复制填充或描边颜色时另一部分也可能随之改色。对**已有对象**只说“一样大”仍会澄清；创建**新基础图形**时明确说“和它一样大”，则从参照对象读取当前外接宽高。
- 方位参照：另一个对象还能给**落点**定坐标（“在方形下面建一个圆”“在第二个上面建一个文字”）。参照物按形状名、序号或标签说出时由候选解析；只说“在它下面建”时仍沿用会话焦点，不需要候选。参照物只提供位置，自身不被修改，也不算目标——两者撞在一起时如实澄清，不会把对象移到它自己旁边。“把某对象移到另一个对象旁边”的参照是同一格，落点与移动共用它。
- 句中同时出现参照物和一个序号时，那个序号属于参照，不再算成要操作的目标：「把第一个挪到第二个右边」只移动第一个。旧实现会把“第二个”当成第二个目标，两个一起挪 16 像素且不报错。参照物是按形状名说的时候不受这条影响——「把第一和第二个挪到方形右边」仍然改两个。
- 用户文字从原转写按偏移截取，绝不静默纠正。引号中的错字、数字、否定词保留原样；有实质歧义先询问。
- 连续监听不会因没听清或指令失败退出；权限拒绝/设备不可用等致命错误才停止。点击麦克风可直接停止；口头停止请求也由 Jev 判断。
- 每条指令轮到执行时读取最新画布。错误/澄清清空后续队列，保留监听；可以补充缺失部分。画布或选区改变会使旧澄清上下文失效。
- “取消待执行”中止客户端等待、清空队列和待澄清内容，并停止监听；已发出的远端请求可能仍完成，但不会落笔。已完成的操作用撤销处理。
- 请求期间页面、图形或选区变化则拒绝应用旧结果。单个最终转写的依赖步骤作为一组撤销，失败原子回滚。

默认 tldraw 形状共用轮廓/填充颜色；整体改色保留填充模式，明确填充才填实。不支持任意 HEX 色、精确圆角、像素描边宽度、把**已有对象**整体尺寸设为参照对象的宽高、旋转、编组、Frame 容器、Figma 组件/变量或任意复杂分组。改变取景只支持“看全部”与“聚焦选中”两种，不支持缩放档位与平移——“放大”“缩小”一律按修改对象尺寸理解，不去猜用户想改镜头还是改对象。未支持的组合原则上拒绝执行；跨类型参照创建存在下文所述的已知缺口。
把新图形建在另一个对象内部（“在方形中间画一个圆”）目前做不到——没有“内嵌”这个落点，能做的只有贴到某一侧。这种情况如实说清可用的说法，而不是回“请说明画布落点”（用户明明说了落点）。

### 复制与跨类型参照创建

当前的“再复制两个”会复制唯一的当前对象，保留原类型和样式，并按指定方向排列；它不会把圆变成方形。真实 Jev 测试中，“复制它”“复制一个圆”仍可能要求澄清，演示复制时使用已验证的“再复制两个”。

“在它下面画个和它一样大的方形”**已支持同尺寸创建**：Jev 分开判断新对象类型、方位参照、尺寸范围和尺寸参照；命令带参照对象 ID，执行层在落笔时读取当前画布外接宽高。真实页面测试中，圆放大到 154×154 后，方形实际也是 154×154；“在圆下方建一个跟圆同样大小的矩形”也通过。普通的“在圆下面建一个矩形”仍建默认尺寸。只说“在圆下面建一个一样的方形”会澄清属性范围；同时要求大小和颜色一样会拒绝，均不会静默只做一部分。颜色、填充、文字和连接关系尚不能随跨类型创建一起继承。

继续扩展这一能力时，沿用**新对象类型、落点参照、尺寸参照和待继承属性**的独立角色；Jev 判断语义，执行层读取真实画布并校验。泛称“一样”继续澄清，不能静默丢弃约束，也不能擅自继承文字、连接或锁定状态。下一阶段若加入样式继承，应覆盖换说法、不同图形类型与样式、多个同类参照，以及否定和不支持属性时画布不变。

## 判断与执行边界

```text
原始语音转写 / 文字
 → 去重、顺序队列、实际画布快照
 → /api/interpret → Jev 类型化判断
 → decision + 置信度 + 原文/数字校验
 → 实际目标类型/存在性/锁定/页面检查
 → tldraw 写入、程序生成“理解为……”
```

候选上下文最多 80 个当前页面对象：ID、种类、文字（每个最多 300 字）、选区/焦点、边界坐标、基本样式；最多 120 条绑定关系，最近成功操作和类型计数。连接关系按对象折叠成“连入／连出”标签附在候选上，模型不必自己把 ID 关联到关系列表；每道候选题只列真正可能入选的对象——关系锚点题只给连过线的，方位参照题给全部候选——都不让候选集随无关信息膨胀。候选截断有标志；不发送音频、凭据、整份文档或任意元数据。音频由浏览器语音识别服务处理。

一条原子指令只发 **1 次 Jev 请求**，同时判断动作、目标、属性、语音噪声、内容片段和歧义；不生成整句改写，不另发纠错/文字提取请求，也不因置信度低重试。保留多分句能力：关系判断一次，加每个分句一次，最多 4 次。只有明确可执行的 decision 和本分支所需判断全部通过才执行。否定、无关、歧义均保留画布。取景请求是唯一例外：它改变相机而不改变画布，实测“看全部”“全览”的 decision 概率只有 0.46–0.83（判为与画布无关），按编辑请求判定它永远进不来，所以它不先过“这是否一个编辑请求”这一关，也不参与那道题的置信度合成。这道题只在明确命中时短路，未命中（none、unknown 或置信度不足）不留下任何影响，正常指令的流程完全不变。在这道题之前还有一层本地直通：整句等价于闭集取景口令时直接兑现，既不进这道题也不发请求——所以没有配置密钥时“看全部”“看镜头”照样能取景。

删除与移动还多一处同类放行，条件收得更紧：句中出现近指历史对象的说法（“刚才建的”“刚画的那个”“上一个”）时，`decision` 会在“编辑这个对象”和“收回那一步”之间摇摆（实测 execute 只有 0.42–0.76，而 `operation` 每次都 0.97 以上判出删除或移动）。这时以操作维度为准，但仍要求句中确实有近指词、不含“撤销／撤回／回退”、且不是疑问句——不含近指词的含糊句照旧被门控拦下（“大一点”可能指镜头，“在这里加一个菱形”可能只是描述），`server/delete.test.ts` 锁住这条边界。

置信度门控同时看 `confidence` 和分布里的 top 概率。`confidence` 是把整条分布压成一个数的派生值，候选项越多、同样阈值对应的 top 概率越低（80 个候选时约 0.81，4 个候选时 0.85），选对象这类候选项最多的题反而最容易通过，所以另外要求 top 概率过一个与候选项数量无关的下限。判断不够明确时，用分布里概率最高的两个选项生成具体问题（“你是指「矩形」还是「菱形」？”），而不是只报一个字段名。合成层自己写下的拒绝理由也直接作为澄清文案给用户，不再被按字段名回放成通用问句——“还不支持移到画布的极值位置”和“你想执行什么操作？”说的不是一件事，字段名只供前端分类。

代码负责原文截取、精确数字/单位、坐标与对齐位移的数学、候选有效性、实际写入、队列和撤销；Jev 不能生成任意 ID 或模型估算值。旧本地解析模块和旧命令协议入口已删除。

主要文件：`server/app.ts` 统一 API 与状态；`server/live/` Jev 问题/上下文/类型合成；`src/jev-validation.ts` 协议校验；`src/live-editor.ts` 执行与约束；`src/App.tsx` 监听/队列/反馈；`src/connections.ts` 绑定连线。

### 当前 Jev 架构与重构进度

项目按“画布发生什么变化、哪些对象分别承担什么角色、要改哪个属性、参数是什么”组合命令。Jev 负责理解这些语义，代码用真实画布状态解析对象、校验命令并执行。本轮已新增 `editFrame`（创建对象／修改现有对象颜色／连接两个现有对象）和 `colorRole`（整体颜色／填充／描边），先让这三类变化有独立的语义判断，再与原有 `operation`、`operand` 等答案合成。两层给出相互矛盾的确定答案时澄清，画布不修改。

这是**局部迁移，不是全量重构完成**。第一阶段已移除重复的属性大类和创建约束问题；创建尺寸来源、参照编辑的目标和来源、连线两端共用候选角色解析入口。已迁移的改色帧仍有 `colorRole` 对低置信属性细项的兜底，后续还需收敛。文字、移动、缩放、复制等仍使用原有合成路径；为避免干扰已迁移部分，旧的写字／新建兜底不能覆盖确定的语义帧，近指历史对象的旧放行仅保留给删除和移动。后续扩展应先定义画布变化及对象角色，再接入命令协议并收窄对应的旧路径；不要给单一说法加专用判断，也不要把旧问题整体注释掉，否则未迁移功能会失效。具体约束见 `AGENTS.md` 的“当前重构进度与扩展路径”。

澄清状态下，完整新指令先按独立请求判断，避免上一句的属性或动作污染它；简短补充才按“原请求的已给角色 + 本句所补的值”解释。真实页面已验证“第二个宽度设为20还是30像素”后补“200像素”会只把第二个的宽度改为 200；完整的新指令“把第二个填充改成和第一个宽度一样”在此前有澄清时不会被误执行为宽度修改。简短补充可能比正常单句多一次 Jev 请求。

测试覆盖 decision 门控（含“撤回已完成的操作”与否定分离、回退不受价值维度影响）、无密钥及旧参数绕过、原文文字保护、数字歧义、单请求约束、类型约束、澄清补充、语音去重和队列；`server/relation.test.ts` 另覆盖关系方向判定、参照编辑合成、关系与参照协议的非法组合拒绝，以及置信度门控随候选项数量的漂移；`server/order.test.ts` 覆盖对齐六向与层叠四向的映射、两种居中不会塌成一个方向、秩序关系不明确时澄清、锁定与重做的合成，以及这些操作的非法组合拒绝；`server/targeting.test.ts` 覆盖空目标集合的框选提示、多对象操作与单对象操作的数量边界，以及“没有可翻转对象”只返回空数组、必须由调用方报错这条契约；`server/view.test.ts` 覆盖取景请求在编辑维度之前短路、豁免只属于取景请求本身（含糊的 decision 对普通指令仍要拦下）、低置信或 unknown 的取景意图不吞掉正常指令、取景命令保留自己的置信度而不继承编辑门控，以及协议只接受两种取景目标；`server/fast-path.test.ts` 覆盖本地直通的整句等价匹配、句末标点与语气助词的容忍，以及复合句和“放大”这类歧义词一律不被本地层吞掉；`server/delete.test.ts` 覆盖序号删除（单个／并列／范围）、整类删除、属性与文字删除的合成与协议校验，以及近指历史对象的句子在整句意图摇摆时由操作维度放行的边界（不含近指词或疑问句仍要拦下）；`server/undo-shortcut.test.ts` 覆盖 `undo` 短路只在操作维度明确时生效（含“不要撤销”“别撤回”这类反向指令不得误入），以及有依赖的多分句接受 `current` 与 `previous`、仍拒绝指向别处的分句。单元测试的模拟 Jev 响应只验证程序，不代表模型准确率。

本轮「撤回已完成的操作」的判据来自服务端探针（`work/undo-probe.mjs`、`work/revert-noul-probe.mjs`：真实密钥、真实请求，同时覆盖“画布上刚做完一步”和“空画布”两种上下文，并对比了 `noul` 与 `choice` 两种原语的判定）。结论是换原语不改变结果——「算了」两种原语都判为非撤回。这一轮**没有在真实编辑器 UI 内验证**：撤销反馈文案的显示、撤销后 `lastEdit` 置空之后的后续行为，都还没有在页面里跑过。

模拟 SpeechRecognition + 模拟 Jev 单独验证连续监听、顺序新上下文、原文转写、澄清及取消。实际编辑器的确定性测试单独验证选区与明确类型冲突、缺失/多候选、类型不符拒绝、连线绑定与撤销。真人麦克风尚未测试。前端构建仍有既有大包体积提示。

本轮新增的两组说法补了确定性测试：`server/connect-sequence.test.ts` 锁住序号端点（两个序号就足以定下两端、方向按原句出现顺序而不是升序、没有两个序号时仍走候选 ID 路径）；`server/delete.test.ts` 增加“清空画布＝全部对象”以及“带序号或形状名的清空不受影响”。

**关系定位与参照编辑已用真实密钥复测**（`work/demo-script-probe.mjs`、`work/demo-answers-probe.mjs`：真实密钥、真实请求，按剧本推进逐个阶段摆出候选、连线、选区与焦点）。三个带标签的图形加两根箭头下，「把连到“结束”的那个矩形改成橙色」「把连到“处理订单”的那个圆形锁定」「把连到“结束”的矩形改成和圆一样宽」在连续三次复跑里都执行成功：目标由真实绑定筛出唯一一个，宽度从参照对象的真实边界读出。方向说反的（“从‘开始’连出去的矩形”）三次都没过锚点门控，如实澄清而不是猜。复测同时推翻了一个旧示例：「把连到‘结束’的方框调成和‘开始’一样宽」在句中出现第二个引号标签（“开始”作尺寸参照）时锚点判定摇摆，三次只过一次，已从演示脚本里换成不带第二个标签的表述。

**本轮新增的对齐、层叠、锁定与重做已用真实密钥验证判断层。** `work/order-probe.mjs`（真实密钥、真实请求）覆盖对齐六向、层叠四向、锁定／解锁、重做，以及互斥边界（“排成一行”“横向排列”“纵向排开”必须仍判为排列而不是秩序关系）。修题面之前对齐与锁定大多被驳回，原因不在新操作本身：`decision` 题把“只说一个动词、不提对象”当成了动作含糊（实测“解锁”的 execute 概率只有 0.54），而 `target` 题在“它们／这些／这几个”这类复数指代上与“省略目标”平票（top 0.48–0.83）。把“不提对象不使本题含糊”与“单数代词和复数指代不是一件事”写进 criteria 之后，对齐 6/6、锁定 4/6、层叠 3/5 可执行，`operation` 与 `orderRelation` 的判定全程正确（top 概率 0.92–1.00）。剩下的驳回都是真歧义（“往下一层”“把它解开”“再来一次”）或擦边（“往上移一层”的秩序关系 top 0.83，低于 0.85 门槛），没有被强行放行。

上一轮复跑撤销探针时，“撤销”“撤回刚才那一步”是靠 `decision` 直接判 `revert`（0.99）通过的；本轮同样两句话已经落在 negated 0.82–0.89 上，是滚动模型上的判定漂移，不是代码回归——`operation` 短路正是为这种漂移留的兜底。

**为三段演示脚本改了三处题面。** `target` 题的 `object` 选项把“在某个对象下面建一个新图形”里的落点参照误当成对目标的引用限定，`explicitType` 题又被句中那个新对象的类型词带偏，于是“在矩形下面建一个菱形”判不出“新建”与“引用”的区别（`explicitType` 的 none 只有 0.63–0.79，够不到 0.85 门槛）；写清“新建说法里的图形名不属于已有目标”之后，「在它下面建一个菱形」「在它下方再建一个矩形」稳定通过。`relationAnchor` 在句中出现第二个对象标签时摇摆，补上“只认连接方向那句话里的对象”之后三句关系指代稳定通过。`operation` 把“调成和某对象一样宽”与“放大”判成平票（0.54／0.46），在 criteria 里点明“把值说成另一个对象的尺寸属于 set”。另外把 `layout` 的“排成一行／排成一列”写明为已给方向、把 `clauseRelation` 的“同一动作落到不同序号目标”写明为多个独立操作，这两处此前会被判成方向不明与单一操作。

**多分句与撤销各修了一处。** 有依赖的多分句原先要求后续分句的目标必须是 `previous`，而 Jev 常把“它”判成 `default`（由代码映射为 `current`）——两者在执行层都指向 `add` 之后被选中的那个对象，所以校验放宽为接受两者：「在这里建一个圆，然后在它里面写“开始”，然后把它改成绿色」现在是可执行的三步（4 次请求）。撤销的修改见上一段，`server/undo-shortcut.test.ts` 覆盖这两条路径，含反向指令不得误入。

**改变取景的判定层已用真实密钥验证。** `work/view-probe.mjs`（真实密钥、真实请求）覆盖 21 句：“看全部／全览／看整体／看整个画布／看全貌／让我看到全部内容／镜头拉远看全部”7/7 判为 fit，“聚焦到选中的／只看选中的／看选中的那个／把镜头对准这几个”4/4 判为 selection，取景题的 top 概率 0.87–1.00。互斥边界是这轮最该确认的事，结果干净：8 句普通编辑指令（“放大一点”“缩小”“大一点”“把它改成蓝色”“撤销”“让它们左对齐”“在这里建一个圆”“把它们排成一行”）的取景判定全部是 none、top 概率 1.00，一句都没被抢走；两句纯聊天（“我得看看这个到底怎么回事”“看看效果怎么样”）也判 none，照旧走“没有明确受支持画布操作”。

口令式的短说法要挑词：“看看全部”可执行（fit 0.99），但“看镜头”“看画面”“镜头归位”在模型侧都不成立——实测“看镜头”判 none 0.39／unknown 0.35，top 只有 0.54。中文里“看镜头”本指“看向摄像机”，不含调整取景的意思，为它单独加一条模型规则正是特例化。**所以它没有进题面，而是进了本地词表**：取景口令现在由本地直通兑现，闭集词表想加一个词就加一个词，“看镜头”因此可用，也不受模型理解边界的限制。判据是歧义性而不是长短——“放大”既可能指镜头也可能指对象，仍然必须交给看得到上下文的 Jev。

**删除与近指对象的判定层已用真实密钥复测**（`/api/interpret` 真实请求，候选题为三个带序号的对象）：序号删除 6/6（“把第三个删除”“删掉第三个”“第三个删了”“把第二和第三个都删掉”“删掉最后两个”“删除全部方形”），属性与文字删除 2/2（“把第三个的填充删掉”“把第二个里写的字删掉”），近指历史对象 3/3（“把刚才建的删掉”“删掉刚才那个”“把上一个删了”）。对照句“把刚建的那个删了？”（疑问）与不含近指词的含糊句没有被放行。同一轮的探针还发现“把第一个挪到最右边”原来落到默认 16 像素上（看上去挪了、其实只动一点点），现在如实拒绝并给出可用说法。删除类指令本轮仍未在真实编辑器 UI 内跑过，只经过类型检查、单元测试与判定层复测。

**取景与秩序操作的执行层尚未在真实编辑器内验证**：`zoomToFit`／`zoomToSelection`／`alignShapes`／`bringToFront`／`toggleLock` 写入后的实际视觉效果、相机动画期间的观感、空画布时说“看全部”的报错、没有选中时说“聚焦到选中的”的降级文案、锁定后对象无法被选中时保留的焦点是否仍有意义、重做与撤销交替时的历史边界，以及没框选时的框选提示与“已锁定／没有锁定”这类报错在页面上的实际显示，都只经过类型检查与单元测试。本轮新增的本地直通同样如此：命中时的界面反馈与零延迟观感、没有配置密钥时说“看全部”“看镜头”能否照常取景，都还没有在浏览器里跑过。
